# Правила карусели: план, slides.json, дизайн

## 1. План слайдов
- Размер: 4:5, 1080x1350 по умолчанию. `"ratio": "3:4"` (1080x1440) или `"1:1"` - только по просьбе. Только статичные PNG; анимированные слайды не поддерживаются - скажи об этом и предложи статичные.
- 5-10 слайдов (Instagram позволяет 2-20). Меньше сильных слайдов лучше, чем вода.
- Слайд 1 (обложка) - крючок. Должен работать один, в ленте и в сетке профиля: конкретное утверждение, проблема или результат плюс причина листать. Не обложка из одного логотипа или названия.
- Слайд 2 сразу даёт пользу: без вступлений и «в этой карусели».
- Одна мысль на слайд: заголовок и не больше ~30 слов, или одна схема с короткими подписями. Не влезает - дели на два слайда.
- Предпочитай форматы, которые сохраняют: шаги, чек-лист, до/после, сравнение, число и его смысл, ошибка и её исправление.
- Последний слайд: вывод одной строкой и призыв (подписаться, сохранить, написать - как скажет пользователь). На последнем можно `"chrome": false` для чистого финала.
- Недостающие данные - на слайде как `[TBD: что нужно]` и в отчёте; никогда не выдумывай цифры, результаты, интерфейсы продукта или логотипы пользователя. Справочные факты и формулы - только проверенные в интернете и с источниками в отчёте (`rules/fact-check.md`).

## 2. Контракт slides.json (carousels/<slug>/slides.json)
`{"handle": "@name", "next": "листай", "ratio": "4:5", "slides": [{"html": "...", "css": "...", "chrome": true}]}`
- `handle` можно не писать: берётся из `brand/brand.json`. `""` - без подписи.
- Рамка (рисует шаблон): handle слева вверху, NN / NN справа внизу, надпись `next` со стрелкой акцента слева внизу (кроме последнего слайда). `chrome: false` прячет всё это на слайде.
- Область контента: `.box`, 920 x 1070 px на 4:5 (920 x 1160 на 3:4, 920 x 800 на 1:1), flex-колонка по центру по вертикали с отступом 36 px, лишнее обрезается. Дочерние элементы можно ставить absolute, если css слайда так задаёт.
- `html`: обычный HTML и inline SVG. Без скриптов, обработчиков событий и внешних ссылок (vid их вырезает). Иконки: `<i data-icon="ИМЯ" class="accent lg"></i>` (Lucide; `tools/vid icons СЛОВО` - имена, слово по-английски), цвет = currentColor.
- `css`: правила вкладываются внутрь слайда (пиши `.x { ... }`). Только переменные темы: `--bg --panel --panel-2 --text --muted --accent --accent-hi --edge --line`, шрифты `--font-sans --font-accent`. Острые углы.
- Классы: `.display` (124 px заглавными, обложка), `.h1` (96), `.h2` (64), `.body` (40), `.small` (28, приглушённый), `.lbl` (подпись заглавными с квадратиком акцента), `.card` `.card.hot` `.chip` `.chip.hot` `.mark` (выделение блоком акцента) `.ser` (акцентный шрифт курсивом) `.muted` `.accent` `.row` `.col` `.center` `.line` `.tk` (уголки акцентом) `.shadow` `.icon` (+ `.sm` `.lg` `.accent`).
- Шаблон: `tools/hyperframes/compositions/carousel.html`. Его классы повторяют talking-head.html - меняй оба вместе.
- Самый быстрый путь: скопируй `examples/carousel/gen_slides.py` в `carousels/<slug>/gen_slides.py`, рисуй каждый слайд как HTML + inline SVG с явными координатами, затем `python3 gen_slides.py && tools/vid carousel carousels/<slug>`.

## 3. Дизайн
- Стиль постоянный (`rules/style-rules.md`): те же цвета, шрифты, сетка и акценты, что в видео. Никаких новых цветов и шрифтов.
- Графика - полезные схемы, а не украшение: каждый содержательный слайд несёт конкретную наглядную схему, которая сама объясняет мысль - настоящий механизм с настоящими подписями и настоящим примером. Параллельность -> задача, разложенная на дорожки на таймлайне, где видно исчезнувшее ожидание; стоимость -> шкала, заполняющаяся шаг за шагом; настройка -> настоящее дерево файлов или фрагмент с выделенной строкой. Кто посмотрит только на картинку, должен что-то узнать.
- Никаких заглушек: не «иконка + заголовок» в карточке, не пустые рамки, абстрактные фигуры или размытые подписи вместо содержания. Иконка - максимум вспомогательный элемент внутри схемы.
- В схемах - настоящие названия, команды, имена файлов и настоящие цифры пользователя; если нужно иллюстративное значение - подпиши его как пример и перечисли в отчёте.
- Графика делается под ЭТУ карусель: диаграмма, поток, таймлайн, столбцы, до/после, макет интерфейса или терминала, фрагмент с пометками, чек-лист с состоянием. Не одна и та же карточка на каждом слайде.
- Виды слайдов: крючок, утверждение, список, шаги, число, сравнение, цитата, чек-лист, процесс, призыв. Соседние слайды - разные механизмы; самую сильную графику - на ключевую мысль.
- Крупный шрифт для телефона: body >= 40 px, подписи >= 26 px, заголовки >= 64 px. Главный объект занимает минимум ~70% области по ширине или высоте.
- Контраст: `hyperframes check` отмечает текст ниже WCAG AA; не ставь текст цветом `--accent` на `--bg` мелким кеглем (бери `--accent-hi` или `--text`).
- Эмодзи внутри SVG `<text>` рисуются пустым квадратом: используй иконку или слова.

## 4. Проверка (vid carousel печатает предупреждения, затем DONE)
- `tools/vid carousel carousels/<slug>` запускает `hyperframes check` (ошибки, вылезание за рамку, контраст) и пишет `out/NN.png`, `out/sheet.jpg` (все слайды на одном листе) и `out/report.json`. Слайд, где контент не влез, получает красную пунктирную рамку.
- Исправь все предупреждения, затем один раз посмотри `sheet.jpg`: порядок чтения, одна мысль на слайд, сила обложки, размер текста. Не больше 2 кругов правок.
